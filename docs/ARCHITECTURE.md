# Housie Salesforce architecture

## Storage allocation

- `Housie_Account__c`: human account/profile and current account-wallet projection. Created only by an authenticated platform operator through Apex permission `HOUSIE_SUPER_ADMIN`.
- `Housie_Operation_Lock__c`: one infrastructure-only singleton row (`Lock_Key__c=GLOBAL`) used with `SELECT ... FOR UPDATE` to serialize Apex write commands.
- 15 Big Objects: the 15 non-account logical entities from `final_data_model.md`.
- `Operation_Journal__b`: technical Big Object commit journal. This is infrastructure metadata, not a product entity.

All Big Object writes use `Database.insertImmediate()`. IDs are generated by Apex as 36-character lowercase hex values. Composite primary indexes are declared in metadata and must not be changed after deployment.

## Important consistency boundary

Big Objects are non-transactional. This project uses a serialized Apex command path and a journal marker written last. Every record carries `Operation_Id__c`; application reads must accept only records whose journal is `COMMITTED`. If any write fails before the final marker, the command returns an error and leaves a PENDING journal record for repair. This provides fail-closed visibility, not a true multi-record database transaction. It cannot guarantee rollback of already-inserted Big Object rows.

The supplied specification's strict atomicity requirement is therefore approximated with an application commit protocol. If absolute all-or-nothing storage rollback is mandatory, Big Objects alone cannot satisfy it.

## Account identity

The account key is a 32-character opaque random token, not a Salesforce record ID. It is currently also the URL context token for the initial shell. This is not sufficient authentication by itself for a public deployment: implement a separately authenticated invitation/session flow with expiry, revocation, replay protections and rate limiting before enabling public account-specific actions. The current resolver only resolves active account context.

## Experience Cloud

Big Objects have no standard record detail pages, list views, sharing rules or OOTB UI. The custom `Housie_Account__c` record can use standard Experience Builder record detail components for profile/account context, but that page does not automatically render Big Object-backed boards, tickets or games. Those remain custom LWC/Apex experiences. The included `housieApp` LWC is the application shell; build the remaining domain screens as LWCs calling Apex controllers. ExperienceBundle/site activation is org-specific and must be completed in Experience Builder after deployment.
